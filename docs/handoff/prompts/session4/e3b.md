## Required corrections

C1 (HIGH) — restrict only on Moved. state.rs ~878-901 composes with the full installation probe, which returns InterpreterBroken when manifest.env_id != active.id (probe.rs ~217-221) — exactly the crash window between ManifestPublished and Committed — so the app goes restricted, ReconcileStartup is skipped, and Rebuild is refused with relocation_recovery_required because of the manifest_published journal (permanent lock); a transient probe timeout also restricts the whole app. Fix: the compose-time decision compares roots only (canonical current root vs recorded root; fall back to normalized text comparison when the recorded root cannot be read) and spawns no interpreter. Remove the inspect early-return in activation.rs ~141-152. In application environment/setup.rs ~85-95 refuse non-Rebuild modes only for Moved (D2: Repair, ChangePython, SwitchVenv and ChangeTorch stay allowed when the interpreter is broken — they create a new env and never mutate the broken one). Tests (desktop state/recovery_tests.rs): `interrupted_activation_is_reconciled_instead_of_restricted` (same root, candidate Verified, run manifest_published/Running, DB active = previous env -> services().is_ok(), active = candidate, run Succeeded/Committed) and `broken_interpreter_keeps_normal_composition` (same root, pyvenv.cfg version mismatch -> services().is_ok() and phase RebuildRequired(InterpreterBroken)).

C2 (HIGH) — reconcile current-root runs in restricted mode. A crash during a moved-root rebuild leaves the Rebuild run Running; after restart the app is restricted without reconciliation (ensure_idle -> SetupInProgress, Retry -> NotRetryable, Cancel -> NotCancellable, setup.rs ~534-543) = permanent lock. Fix: in state.rs ~963 run ReconcileStartup under the gate before returning the restricted state (it already skips foreign runs, activation.rs ~156); then re-read the manifest and, if the root no longer counts as moved, continue with normal composition (D3: detection still happens first). Tests: `restricted_start_reconciles_only_current_root_runs` (current-root Rebuild Running -> Interrupted and a Retry or new Rebuild is accepted; a copied old-root Running/Intent run stays byte-identical; a current-root Intent run with a Verified candidate -> the manifest at the current root names the candidate with install_root == current) and application `reconcile_startup_processes_current_root_runs_when_moved`.

C3 — status precedence. queries.rs ~179-186 shows rebuild_required while the rebuild itself runs. Put `run.status.is_active() && same_location(run.request.install_root, root)` -> RunInProgress before the RebuildRequired arm. Test `rebuild_status_reports_run_in_progress_while_rebuilding` (current-root Running -> RunInProgress; a copied old-root Running run -> RebuildRequired(Moved)).

C4 — chained relocation. A->B accepted, rebuild fails, then the install is copied B->C; accept(A,C) only rebases paths under A, so env path/authorized location still point into B and deleting an env from C would delete B's copy. Fix (persistence.rs ~210-256): rebase from {recorded old root} plus every install_relocations.old_root/new_root, excluding the current root, using the longest component prefix. Test `chained_relocation_rebases_paths_from_every_recorded_root` (accept(A,B) then accept(A,C): owned path, base and authorized end up under C with exact text, state repair_required; external paths unchanged).

C5 — never store verbatim prefixes. existing_or_recorded canonicalizes and new.join(tail) inherits the `\\?\` prefix (persistence.rs ~36-41, 63-72). Use canonical paths only to PROVE a path is under the old root; store the non-verbatim spelling (the python::normalize_path convention). Strengthen `relocation_rebases_authorized_locations_without_touching_external_paths`: exact stored text == path_text(normalize_path(new.join(..))), does not start with `\\?\`, and path == authorized.

C6 — logging before compose. lib.rs ~97-105 starts logging after compose, so reconcile reports and "could not open its install root" are never logged. Fix: once resolve_root() is Ok (and the root is not missing), create only <root>/data/logs and start logging, then compose. A missing root (root_missing) must still create NO directories (keep `missing_bootstrap_root_creates_no_install_directories` passing).

C7 — quiesce only after a successful rebuild. env_commands.rs ~189-190 shuts down downloads and the library before the rebuild runs; if it fails both stay stopped for the session. Fix: quiesce on success right before the restart — simplest: TauriShell::request_restart (app_lifecycle.rs ~62) shuts them down then restarts (note AppHandle::restart skips RunEvent::Exit handlers), and drop the per-command calls (~241-242, ~257-258). Keep the open/new-install paths quiescing before their restart too.

C8 — limit open_existing journal refusal to relocated candidates. opener.rs ~265-270 refuses an unmoved install whose journals startup would recover (e.g. an update run awaiting recovery -> the user can never reopen their own install). Refuse only when the candidate's install_root differs (component-aware) from the destination. Tests: change the existing refusal test to use a relocated candidate; add `open_existing_allows_an_unmoved_install_with_startup_recoverable_journals`.

C9 — tighten the original-root assertion. `moved_rebuild_preserves_files_and_launch_options` (crates/infrastructure/tests/workflow/relocation.rs ~312-318) only checks the old root's install.json, checkout and owned env. Assert the whole original root tree is identical (incl. data/app.db bytes; no new envs/ or data/tools entries).

C10 (low) — compose_recovery must not fail on bootstrap_path() (state.rs ~1057 uses `?`; no config dir would fail recovery startup). Leave the opener unset; opener() then returns root_switch_failed.
