
## Build environment and repository rules (mandatory)
- Read `docs/handoff/tooling/coder-env.md` and `AGENTS.md` in your working copy first. Build with the default MSVC toolchain pinned by `rust-toolchain.toml` into the default `target/` dir; do NOT set RUSTUP_TOOLCHAIN or CARGO_TARGET_DIR. Use Git Bash or PowerShell. The GNU env (`docs/handoff/tooling/gnu-env.sh`) is a fallback only if MSVC linking fails for toolchain reasons (report it).
- MEMORY IS TIGHT (about 3 GB free, another Rust build may run concurrently on this machine): always pass `-j 3` to cargo build/test/clippy, prefer targeted `-p <crate>` runs while iterating, run the workspace-wide commands once at the end. Never run two cargo commands at once yourself.
- Rust: rustfmt, clippy `-D warnings`, no serde/tokio/reqwest/rusqlite/tauri in domain or application, ports via async-trait `Arc<dyn ...>`, composition only in crates/desktop/src/state.rs, errors per layer with thiserror. Match surrounding style and comment density.
- TypeScript: 2-space, single quotes, no semicolons, kebab-case files, Tauri access only via ui/src/shared/ipc/gateway.ts. Never hand-edit ui/src/shared/ipc/bindings.ts; regenerate only with `cargo test -p desktop --test bindings --locked -j 3 -- --ignored export_bindings`.
- Generated permission TOMLs under crates/desktop/permissions/autogenerated/ are produced by the build; keep new ones, ignore line-ending-only noise.
- Do not commit, push, stash, reset, or touch git history. Do not modify files outside the stated scope. If the spec is underspecified or conflicts with the code, stop that item and report the gap precisely instead of improvising.
- Git tests must actually execute (git is on PATH); a skipped `require_git!` is not evidence.
