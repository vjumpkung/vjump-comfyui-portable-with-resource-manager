## Behaviour
1. Registry browser (FR-NODE-1): search box (debounced), pagination (page/limit, totalPages), manual "Refresh" (refresh: true), shows `fetchedAt` and a "stale (offline cache)" notice when `stale`. Each row: name, publisher, description, downloads, GitHub stars (null → "—" / "unknown"), latest version, repository link (opens via `gateway.nodeOpenRepository`, never `<a href>` navigation), OS/accelerator/ComfyUI support as text+icon chips (`compatible`/`incompatible`/`unknown`, never color-only), flagged/deprecated chips, backend `warnings`. Action: Install.
2. Install dialog: Registry release (optional exact version text; empty = latest resolved once by backend and shown in review) vs Git (only if `repository`; reference optional). Also a standalone "Install from Git URL" entry (https URL + optional branch/tag/commit). Prepare via `nodePrepareRegistry`/`nodePrepareGit` with a client `requestId` (crypto.randomUUID) so `nodeCancel(requestId)` can cancel a long prepare. Then ReviewDialog.
3. ReviewDialog (NFR-SEC-3): show untrusted-code notice, exact source (`sourceLabel`, registry id@version or git url@commit), prior source for updates, artifact/tree/hook digests, requirements (label: "Python requirements (registry dependencies and requirements.txt)"), warnings (require explicit acknowledgement), protected pin changes (require explicit confirmation), install.py checkbox **default unchecked**, "Remember this source" only when a trust namespace exists (git repository, or registry with publisher AND repository), "Also remember install.py permission" only when remember source AND run install.py are checked. Fix the five mismatches: (a) `executeNodeCode` checkbox is always shown and must be checked even for trusted sources (trusted only pre-informs; backend requires true); (b) unchecking remember/hook clears `rememberHook`; (c) consent state is reset whenever plan id OR binding changes (key consent by `${id}:${binding}`); (d) trust option gated on namespace; (e) requirements label. Apply → `nodeCommit(decision(plan, consent))`. Cancel/close → `nodeCancel(plan.id)` discards the reviewed plan (not backend work in progress).
4. Installed table (FR-NODE-5): name, source label (registry version / git commit short + branch / manual), enabled, dependency state chip (`not_run`/`ok`/`failed` text+icon), conflict flag, dirty (true/false/unknown). Filter text + source-kind filter + enabled filter. Keyboard-aware virtualization above 200 rows reusing the library ModelTable approach (`@tanstack/react-virtual`, ARIA grid, one row tabbable, arrows/Home/End/PageUp/PageDown, scroll-then-focus). Row actions: Update (registry/git; for git detached/upstream-less, prompt a reference), Retry dependencies (when `failed`), Enable/Disable (confirm), Uninstall (confirm; note "Python packages are left in place because they are shared"), open repository.
5. Update all (FR-NODE-6 P1): prepare updates sequentially for selected eligible nodes (skip manual/conflict/dirty), show each review (same ReviewDialog consent rules, per plan), then `nodeUpdateAll(items)`; render per-node results (success, error message, cleanupPending) and `stoppedForRepair` banner.
6. Repair / health: when `repairRequired` show a banner with "Repair environment" → `onRepair()` (existing setup facade); most mutating actions disabled except Retry deps/Repair as backend allows. Unresolved operations panel (from `NodeListDto.unresolved`): phase, failure, log tail, "Rescan / finish recovery" → `nodeRescan`.
7. Errors: `IpcClientError` codes → toast + inline. When the backend refuses because ComfyUI is running (find the exact error code in desktop error mapping), offer "Stop ComfyUI and retry" (calls `onStopComfy` then re-runs the same prepare/commit request). After a successful commit/enable/disable/uninstall/update-all, offer "Restart ComfyUI" (start) via callback. Logs: live operation logs from `useNodes().logs` filtered by operation id in a LogView.
8. Unmount/reload never cancels backend work: cleanup only unsubscribes.
