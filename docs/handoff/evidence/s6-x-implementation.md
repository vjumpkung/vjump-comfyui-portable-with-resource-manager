## Deviations, decisions and caveats (none blocks the plan)
1. **Module layout.** The plan says "infrastructure `extra_paths.rs`, writer side". The writer lives in the child module `extra_paths/writer.rs` (tests in `writer/tests.rs`) to keep `extra_paths.rs` small; tests still match the `extra_paths` filter. `extra_paths.rs` only gained the module declaration and the `APP_SECTION` re-export.
2. **Root provider.** `ManageExtraModelPaths` takes `Arc<dyn RootSwitcher>` (the existing provider, `deps.root`), not the whole `EnvironmentDeps`.
3. **Extra validation (fail closed, not in the plan).** A `..` or `.` path component is refused with the "absolute folder path" message, because a lexical `..` could hide an overlap with the app folders. A base that is, or lies inside, a regular file is refused with a new message "The chosen path is a file or lies inside one. Choose a folder." A file named like a standard category in the base is refused with "A file named {name} exists in the model base folder. Move or rename it, then retry." (checked for all 18 names before anything is created). Check order: control characters, then `$`/`%`/leading `~`, then `\\?\`-`\\.\` and absolute, so `~/x` reports the `~` message rather than "not absolute".
4. **Folders created.** Only the 18 section 4.6 names are created; `configs` and the discovered `ComfyUI/models` subfolders become keys but their folders are not created.
5. **Link check.** On Windows each existing ancestor of the base is opened with `FILE_FLAG_OPEN_REPARSE_POINT` and passed to `reject_reparse`; on Unix `symlink_metadata().is_symlink()` is used (the Unix branch was not compiled here, only Windows). Consequence to be aware of: any parent that is a reparse point is refused, including cloud-sync folders that Windows marks that way.
6. **Backup on remove.** `remove` also backs up a file whose first line is not the app header before it rewrites or deletes it (uniform rule: the app never changes a file it did not write last without a backup).
7. **Library refetch in the UI.** The Library page keeps its list in `features/library`, and ESLint boundaries forbid a feature importing another. The refetch is therefore backend-driven: both commands await `library.rescan` (errors logged only), which publishes the normal change notices the library store already consumes. The UI itself refetches the extra-paths list. The restart hint uses ComfyUI `starting` or `running`.
8. **ACL cases.** The generate case sends a relative path so the handler answers with a validation error without writing (the manager test would otherwise create folders in the temp root and fail the "reaches a port" assertion). The remove case is a no-op on that root. Both are `HandlerError`.
9. **Extras.** One additional Vitest (`shows_the_backend_message_when_a_folder_is_refused`) and one pointer sentence in DOCUMENTATION section 8. `atomic_write` creates its temporary file inside `ComfyUI/`; a crash at that moment could leave a `.tmp*` file in the checkout (existing helper behavior).
10. **Not run:** the manual native smoke test (real ComfyUI start with the generated section) and any Linux build.
